# 設計

## 構成

| ファイル | 役割 |
|---|---|
| `Direction.kt` | 頭の向きの判定（正面の決め方・しきい値・1 回の判定 `judge`） |
| `GameEngine.kt` | ゲームの段階と拍の進行、タッチの扱い。グラスへは `GlassPort` 越しに送る |
| `GlassCanvas.kt` | 画面を画像に描き、前と変わった画像だけを SDK のキャンバスに送る |
| `AcchiApp.kt` | SDK の接続・IMU・タッチを `GameEngine` に渡す。Application のスコープで動く |
| `MainScreen.kt`・`LegalScreen.kt` | スマホの画面 |

`GameEngine` は SDK に触れないので、偽の `GlassPort` と kotlinx-coroutines-test の仮想時間で「何を何 ms に送るか」までユニットテストで確かめる。

## 段階とタッチ

```
STANDBY（本体のホーム画面） --2回タップ--> TITLE --2回タップ--> COUNTDOWN → PLAYING → GAME_OVER
   ^                                         |                         |                 |
   +------------------長押し-----------------+   <------長押し---------+  <---長押し------+
                                                                                  2回タップでもう一度
```

- 2 回タップは先へ進み、長押しは 1 つ戻る。シングルタップは使わない（ツルに触れただけで反応させない）
- グラスに繋がるとタイトルを出す。タイトルと結果を 60 秒放っておくと、キャンバスを閉じて本体のホーム画面に戻す
- スマホの「スタート」はどの段階からでもカウントダウンを始め、「やめる」はホーム画面に戻す

## 拍

1 回は 4 拍で、「あっち」「むいて」「矢印」「判定（セーフ・アウト・はやい・おそい）」を 1 拍ずつ出す。始めに「3」「2」「1」を同じ拍で出し、リズムをつかんでもらう。

- 拍の時刻は、始めた時刻からの絶対時刻で決める。描画や送信が遅れても、次の拍がずれていかない
- 1 拍の長さはテンポで決まる（ゆっくり 800ms・ふつう 650ms・はやい 540ms）。セーフになるたびに 15ms 短くし、それぞれ 560・460・400ms で止める。「はやい」「おそい」「とれない」の回では短くしない
- 判定の拍の次の「あっち」までに、顔を正面へ戻してもらう（1.5 拍ほどの余裕がある）

## 判定

矢印の向きは、その回の頭の向きを見る前に乱数で決める。判定はスマホが IMU のサンプルを受け取った時刻で行う。

| 区間（その回の始まりからの拍） | 何をするか |
|---|---|
| 0.5〜1 拍（「あっち」の後半） | yaw と pitch の平均を、その回の正面にする |
| 1 拍〜締め切り | 正面からの角度を見て、最初にしきい値を超えたサンプルで向きを決める |
| 締め切り = 矢印を送ってから 1 拍 − 80ms | これまでに超えなければ「おそい」 |

- しきい値は左右 20°・上下 15°。両方超えたら、しきい値に対してより大きく動いた軸を採る
- 最初に超えた時刻が、矢印を送る 250ms より前なら「はやい」（フライング）
- 最初に超えた向きで決め、あとで向き直しても変えない。矢印を見てから向きを変えても間に合わないようにするため
- SABERA の yaw は磁気センサーで補正されないので、時間とともにずれる。毎回正面を取り直すので、ずれが判定に入るのはその回の数秒の分だけになる
- 左右・上下の符号は公式サンプルに合わせる（yaw が増える向きが左、pitch は上向きが負）。実機で逆なら、スマホの設定で入れ替える
- 正面を決める区間か、見はじめてから締め切りまでの区間にサンプルが 1 つも無ければ、その回は判定できないので「とれない」と出す。BLE が一時的に途切れただけのこともあるので、「はやい」「おそい」と同じく数え、3 回つづいたら終える

## グラスの表示

- キャンバス（576x360）に 2 枚の画像を置く。id 0 は真ん中の大きな文字か矢印（88,64 から 400x160）、id 1 は下の小さな 1 行（88,240 から 400x48）
- 画像はすべて、キャンバスの中心から左右 240 px・上下 120 px の範囲（48,60 から 480x240）に置く。SDK の資料はキャンバス全体に置けるとしているが、見える範囲は書いていない。0.1.0 の実機では、y 40〜224 に置いた画像は全部見え、y 280〜336 に置いた下の行は下側が切れて見えた。0.1.1 の下の行（y 240〜288）が全部見えるかは、まだ実機で確かめていない
- グラスの画像バッファは 380,000 byte で、置いた画像の幅 × 高さ × 2 byte の合計と受信中のデータが入る。同じ id を差し替える間に古い画像と新しい画像の両方が数えられても収まるよう、真ん中 2 枚分と下の行 1 枚分の合計を 350,000 byte 以内にしている
- 1 つの id は、置いている間ずっと同じ場所・同じ大きさにする。同じ id を別の場所や大きさで差し替えると、前の画像の一部が画面に残ることがある
- 前の画面と変わった画像だけを送る。遊んでいる間の下の行（れんぞく N）は、数が変わる拍にだけ送る
- 黒地に白の 2 値で描く。グラスでは黒が透けるので、明るいのは文字と矢印だけになる
- 終わるときは `closeCanvas` でキャンバスを閉じ、本体のホーム画面に戻す
- 描いた画像は 24 枚まで覚えておき、同じ言葉を描き直さない。拍ごとに出す言葉と 4 つの矢印は、始めるときに先に描いておく
- 同じ接続のまま切れて繋ぎ直したときは、グラスが何も表示していないものとして、次の画面でキャンバスを開き直して全部送る
